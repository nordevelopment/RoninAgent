## 1. 🎤 Elevator Pitch (Что сказать в первые 60 секунд)

> *"RoninAgent — это автономный персональный AI-агент, спроектированный с фокусом на суверенность данных (100% self-hosted), высокую производительность и отсутствие оверхеда фреймворков.*  
> *Вместо раздутых абстракций вроде LangChain я реализовал ReAct-цикл (Think-Act-Observe) на чистом TypeScript. Это дало холодный старт бэкенда за **менее 1 секунды** и потребление памяти всего **~50-100 МБ RAM** (в сравнении с 1-1.5 ГБ у аналогов).*  
> *Агент умеет полноценно работать с документами (читать и генерировать Excel, Word, PDF), скрейпить динамические веб-страницы через Puppeteer, хранить векторную память локально через `sqlite-vec`, динамически подтягивать скиллы для экономии контекста и управляться как через Cyberpunk Web UI, так и удаленно через Telegram."*

## 2. 🏛️ Архитектурные акценты (О чем говорить гордо!)

### 1) Собственный ReAct Engine (`ChatManager.ts`)
* **Автономный когнитивный цикл:** `User Prompt -> LLM -> Tool Call -> Tool Execution -> Observation -> LLM Evaluation -> Final Response`.
* **Защита от бесконечных циклов:** Ограничение итераций `AI_MAX_THINKING_STEPS` (по дефолту 25) и ограничение длины истории контекста.
* **Auto-Recovery для JSON Tool Arguments:** LLM иногда отдают невалидный или обрезанный JSON (например, при достижении токен-лимита). В `safeParseToolArguments` реализован 3-уровневый fallback:
  1. Санитизация управляющих символов (`\n`, `\r`, `\t`).
  2. Автоматическое дозакрытие оборванных JSON-структур.
  3. Regex-экстракция путей и содержимого для файловых операций.
* **Session Interruption (AbortController):** Возможность мгновенно прервать генерацию и исполнение тулов на бэкенде по сигналу пользователя.

### 2) Безопасность и Sandboxing (`FileSystemManager.ts` & `AITools.ts`)
* **Изоляция в `workspace/`:** Строгая валидация путей через `path.relative()` — агент не может выйти за пределы рабочей директории (Path Traversal Protection).
* **Политика `RequireReadBeforeWrite` (Middleware):** Агент физически не может перезаписать существующий файл, пока не вызвал `read_file` в рамках текущей сессии. Это предотвращает случайное уничтожение данных.
* **Output Truncation Middleware:** Автоматическая обрезка вывода инструментов (до 100k символов), чтобы вывод не сжигал контекстное окно модели.

### 3) Динамические скиллы (Dynamic Skills Routing)
* Вместо того чтобы запихивать гигантский мега-промпт на 50,000 токенов в системный промпт на каждый запрос, скиллы хранятся в модульных Markdown-файлах (`agents/<agentId>/skills/*.md`).
* При входящем сообщении анализируются ключевые слова (Keywords), и нужные инструкции подмешиваются в системный промпт **на лету** только тогда, когда они действительно нужны (e-commerce, coding, web-design, translation).

### 4) Локальный Hybrid RAG & Vector Memory (`MemoryManager.ts`)
* Нет зависимости от внешних тяжелых векторных баз (Pinecone, Qdrant, Milvus).
* Векторный поиск реализован локально через расширение **`sqlite-vec`** внутри `better-sqlite3`.
* Поддерживает семантический поиск по эмбеддингам + keyword fallback через SQL `LIKE`.

## 4. 🧠 Ответы на главные вопросы интервьюеров (Cheat Sheet)

### В: «Почему вы не использовали LangChain, AutoGen или CrewAI?»
> **О: «**LangChain и похожие фреймворки страдают от овер-инжиниринга, гигантского дерева зависимостей, медленного старта и плохой прозрачности: когда агент уходит в цикл или ломается тул-колл, отлаживать 15 слоев абстракций внутри LangChain — это кошмар.  
> В RoninAgent я написал чистый, прозрачный ReAct-цикл на TypeScript. У меня есть 100% контроль над промптом, историей, обработкой ошибок и отменой запросов (`AbortController`). При этом проект весит считанные мегабайты и стартует за доли секунды.**»**

---

### В: «Как решается проблема галлюцинаций в аргументах инструментов (Tool Calling)?»
> **О: «**Во-первых, строгие JSON-схемы инструментов с подробными описаниями.  
> Во-вторых, в `ChatManager.ts` я внедрил 3-ступенчатый auto-recovery парсер (`safeParseToolArguments`): если модель обрезает JSON из-за лимита токенов или забывает экранировать кавычки, пайплайн чинит строку или извлекает параметры регулярными выражениями.  
> В-третьих, результаты выполнения и ошибки возвращаются обратно в LLM в роли `tool`, позволяя модели отрефлексировать ошибку и попробовать другой подход на следующем шаге цикла.**»**

---

### В: «Как вы обеспечили безопасность работы агента с файловой системой?»
> **О: «**У меня реализована многоуровневая защита:
> 1. **Sandboxing:** `FileSystemManager` нормализует пути через `path.resolve` и проверяет через `path.relative`, чтобы результирующий путь не выходил за пределы папки `workspace/`. Любая попытка Path Traversal (`../../etc/passwd`) сразу выбрасывает ошибку.
> 2. **RequireReadBeforeWrite Middleware:** Агент не имеет права перезаписать существующий файл, если предварительно не прочитал его в этой же сессии.
> 3. **Базовая авторизация и Whitelist:** Web UI можно закрыть через Basic Auth, а доступ к Telegram-боту строго ограничен списком разрешенных User ID (`ALLOWED_TELEGRAM_USER_IDS`).**»**

---

### В: «Как устроена память (RAG / Memory)?»
> **О: «**У нас гибридный подход. Краткосрочная память — это скользящее окно истории сообщений в SQLite (`AI_MAX_HISTORY_MESSAGES`).  
> Долгосрочная память — семантическая: факты векторизуются моделью эмбеддингов и сохраняются в локальной таблице SQLite с расширением `sqlite-vec`. На каждый запрос мы делаем cosine-similarity поиск по вектору запроса и подмешиваем релевантные воспоминания в контекст. Если эмбеддинг недоступен, работает текстовый поиск fallback.**»**
